# 可演化世界观工程方法论

## 1. 方法的来源与抽象过程

这套方法不是从一张空白表格出发，而是从一轮完整世界观工程中逆向提炼：先有底层法则和知识分层，随后补足物理账、制度后果、维护与事故，再以一座城市把人口、设施、法域、家庭和历史压进同一实例，最后用反事实审查暴露“接口齐全但生活未闭合”的问题。

设计历程可归纳为六个阶段：

| 阶段 | 解决的问题 | 沉淀出的通用能力 |
|---|---|---|
| 1. 宪章与治理 | 新灵感怎样不破坏核心世界 | 原则、权威状态、知识边界、依赖与变更门禁 |
| 2. 本体与账本闭合 | 力量从哪里来、到哪里去、何时失败 | 能量／信息／物质／权限／身份等分账与不可行域 |
| 3. 横向文明系统 | 重复能力如何成为社会基础设施 | 安全、容灾、观测、制造、维护、经济、职业与中层接口 |
| 4. 社会真实性 | 为什么自洽设定仍像布景 | 六个再生产循环、二十二面、五条耦合链、L0—L6 与压力测试 |
| 5. 地区实例化 | 通用接口怎样成为一座真实地方 | 同一人口—地图—设施—法域—家庭—时间线的交叉闭合 |
| 6. 工具化 | 怎样让简单提示稳定复用上述过程 | 状态模型、确定性校验、模型编排、失效传播和 MCP 边界 |
| 7. 持续迭代 | 多轮扩建怎样不变成候选山与验证表演 | 纵切选择、持久化边界、饱和判断、时间尺度与检查点 |

关键经验是：真实性不能在创作末尾靠“加一些生活细节”补上。它必须从第一条规则开始，沿资源、劳动、制度、差异、日常和历史连续传导。

## 2. 总体模型

世界观工程的主链是：

```text
创意种子
  ↓
核心差异 + 体验承诺
  ↓
可行规则 + 不可行域 + 知识分层
  ↓
输入／输出／代价／损耗／故障／维护／反制账
  ↓
资源、设施、劳动、组织、法律、身份、证据与分配
  ↓
普通日常、危机、一生、十年反馈
  ↓
人物不可回避的选择与故事压力
```

一句压缩表达是：

> 规则 → 代价 → 稀缺资源 → 劳动与设施 → 权力与制度 → 差异化生活 → 历史反馈 → 人物选择。

模型必须允许世界在没有主角和作者救场时继续运行。

## 3. 四种真实

| 真实类型 | 要求 |
|---|---|
| 事实真实 | 可选；世界不必复制现实 |
| 因果真实 | 必须；相同条件产生相容结果 |
| 社会真实 | 必须；人群围绕规律形成劳动、制度、利益和规避 |
| 体验真实 | 必须；规则能进入身体、时间、习惯、关系和物件 |

“硬科学”不自动等于真实。一个物理解释精细、但没人制造、维护、等待、付费、受伤或继承后果的世界，仍只是技术陈列柜。

## 4. 十二项默认原则

项目可覆盖或增补这些原则，但必须显式记录。

| ID | 原则 | 工程含义 |
|---|---|---|
| G-01 | 非人格因果 | 世界规律不因主角身份、道德值得或作者需要改变 |
| G-02 | 先记账，后奇迹 | 输入、输出、代价、损耗、权限和失败先闭合，再决定表现 |
| G-03 | 知识分层 | 作者真相、专家模型、公众常识、角色知识和读者未知分开 |
| G-04 | 重复能力生成制度 | 可规模化的能力必然生成职业、组织、规范、市场、犯罪和反制 |
| G-05 | 人是意义中心 | 机制服务于人的选择、关系和代价，不以术语复杂度为目标 |
| G-06 | 精确与受约束未知并存 | 已知部分可核验；未知必须有边界、证据状态和发现路径 |
| G-07 | 身份与生命连续性不可廉价复制 | 复制记录、功能或外观不自动复制主体、责任、关系或死亡 |
| G-08 | 账本是作者宪法 | 账本约束创作，但不应变成角色可见的游戏面板，除非世界明确如此 |
| G-09 | 外衣与内核分层 | 表层可神秘、诗性、多文化；底层仍有一致的工程约束 |
| G-10 | 跨尺度同账 | 个体法术、城市设施、战争与天体工程使用相容的成本和边界 |
| G-11 | 知识必须可被发现 | 正确理论、错误学说与秘传都需要观察、记录、验证、传承或失传路径 |
| G-12 | 不完美、维护与历史 | 系统有磨损、旧标准、临时补丁、事故记忆、既得利益和路径依赖 |

## 5. 稳定规律与生产性矛盾

需要消灭的矛盾：

- 同一规则无因改变；
- 资源、权限、证据或机构能力凭空出现；
- 时间线互斥；
- 人物获得作者知识；
- 制度只在剧情需要时执行；
- 危机结束后所有长期后果自动清零。

应该保留并解释的矛盾：

- 不同学派对同一现象的相互竞争解释；
- 中央规则与地方执行能力的落差；
- 纸面权利与证明、费用、语言、等待之间的落差；
- 曾防止更大灾难的制度在今天成为压迫；
- 相同自然规则因覆盖、冗余、信用和关系而产生不同社会遭遇。

## 6. 从种子到候选世界的算法

### 6.0 先选深度，不用一把尺处理所有请求

- `seed`：一句灵感的第一轮，只做最小规则、直接后果、一个生活切片、风险缺口与路由；不要求状态文件或填满二十二面。
- `candidate`：准备持续开发或进入人物／故事，建立机器状态，维护相关六环、方面、耦合链与情境测试。
- `instance`：完整城市、文明、制度或正典准备，才要求同一人口—地图—资源—设施—法域—家庭—时间线的全量交叉闭合。

深度可以升级，不能在用户只给一句灵感时用完整工程表惩罚创意。候选内容应先可读、可感，审计随后紧凑呈现。

### 6.1 种子压缩

从用户输入提取五个字段：

1. **核心差异**：这个世界与熟悉世界最不同的因果事实；
2. **体验承诺**：用户真正想感受的气质、处境或关系；
3. **作用尺度**：身体、家庭、城市、国家、星球或多世界；
4. **审美外衣**：奇幻、科幻、神话、武侠等可见表达；
5. **权威边界**：已锁定、可代拟、必须由作者决定。

模型应主动给出少量高质量候选，不应把所有缺口变成用户问卷。

### 6.2 规则原子化

每个核心奇异点拆成“允许／禁止”双条款，再填入成本、失败、维护、权限、痕迹和规模边界。若无法写出明确的不可行域，规则通常还只是愿望。

### 6.3 复杂概念先解耦

仅当概念纠缠会改变因果、权威或历史判断时，先做结构深化短表：

| 部分 | 必须回答 |
|---|---|
| 概念边界 | 它是什么、做什么、依赖什么、失去什么仍存在、明确不等于什么 |
| 历史分层 | 原始压力 → 设计目的 → 实现机制 → 共同故障 → 应急处置 → 幸存底盘 → 现代再利用／误读 |
| 关系裁定 | 同一实体、谱系后裔、制度继承、权限继承、技术依赖、功能趋同、表面相似中的哪一种 |
| 认知生态 | 真实机制 → 可观察现象 → 民间解释 → 仪式反馈 → 解释权组织 → 异端与失败预言 |

“功能相似”不推出血统、法统、权限或技术连续；现代用途也不能倒推为古代唯一目的。宗教与错误知识必须有观察和反馈来源，不能只靠大众愚昧凭空出现。

这个短表是复杂任务的临时推理面，不进入 `world-state` schema。简单节日、单条规则或早期灵感直接跳过。

### 6.4 内生吸引力检查

当用户指出某个国家／组织“只有工具性质”，或要求它尚未直接登场就能持续吸引读者时，先检查它是否拥有独立于主角和邻国需求的内在张力：

1. 移除它与主角、盟友、敌国的关系后，还有什么未完成使命或无法自洽的自我解释？
2. 哪些物件、病人、禁运、边境异常、互相矛盾的证言或制度后果，会在它登场前泄露存在？
3. 它相信自己在守护什么；哪种真相会摧毁这套信念或合法性？
4. 多个候选方向是否在因果核心、伦理代价和揭谜回报上真正不同，而不只是替换名称、资源或视觉外衣？

医疗中心、种源库、盟友、市场、避难所等只是能力或外部接口，不能单独通过检查。若移除外部关系后该对象不再值得追问，应先补 `intrinsic_attractor`，再扩写资源与制度：

```yaml
intrinsic_attractor:
  internal_mission:
  core_mystery:
  self_contradiction:
  offstage_leaks: []
  revelation_cost:
```

### 6.5 涌现式历史重建

当用户要求“让现状从历史中涌现”，不得从古代目的直接跳到现代国家。按以下链条建立中间载体：

```text
古代干预或基础功能
→ 可长期残留的地形、材料与生态底盘
→ 重启／哑火造成的非均匀失效
→ 幸存地点与必要劳动被筛选
→ 技艺沉入家门、禁忌、职业和地方义务
→ 制度与权利从重复问题中形成
→ 复苏强化旧路径
→ 现代国家、阶层与跨国依赖出现
```

同一份 `resolution_brief` 按需增加：

```yaml
historical_layers:
  original_pressure:
  base_function:
  later_overlays: []
  implementation:
  common_failure:
  emergency_response:
  surviving_substrate:
  failure_inertia:
  modern_reuse_or_misreading:
emergence_chain:
  substrate:
  nonuniform_failures: []
  selected_sites_and_labor: []
  social_reproduction: []
  institutionalization: []
  path_reinforcement:
  modern_outcomes: []
contingency_and_necessity:
  necessary_pressures: []
  contingent_forks: []
  locked_outcomes: []
  open_origins: []
non_inheritance_guard:
  excluded_continuities: []
  surviving_dependencies: []
```

古代具体目的、组织或执行时序可以保留为多个假说，但现代结果依赖的物质、劳动和制度约束必须明确。基础功能、后期叠加使命、失效后惯性与现代再利用不得互相倒推；功能趋同不推出法统、血统、产权、权限、技术或人格连续。

古代巨构还须按需补一份 `survival_ledger`，说明它凭什么熬过失效，而不是用“古代魔法”免账：

```yaml
survival_ledger:
  persistence_mechanisms: []
  inputs_or_stored_gradients: []
  decay_and_failure_morphologies: []
  observable_and_negative_ruins: []
  present_maintenance_labor: []
```

### 6.6 后果树

从规则向下至少推三轮：直接物理后果、组织与分配后果、代际与历史后果。每个后果必须能回指上游规则或已声明假设。

### 6.7 实例闭合

选择一个受控实例，把同一人口、空间、资源流、设施、组织、家庭、法域和时间线穿过二十二面。不要用二十二个互不相干的微型故事拼成“完整地区”。

### 6.8 反事实承压

移除主角、削减资源、让设施停机七天、让技术普及十年、让坏人消失、让普通家庭跨境。结果可以变化，但规则不能换轨。

### 6.9 叙事激活

最后才提炼：谁最受益、谁承担隐形成本、谁拥有选择权、谁只有等待、什么角色最能暴露系统的矛盾。故事不是用来遮住缺口，而是用来检验世界。

### 6.10 多轮收敛

持续项目每轮只选一个 `expand`／`connect`／`pressure`／`consolidate` 纵切。通用成熟度显著高于实例成熟度时，停止继续补方面清单，转向同一地图、机构、家庭和时间过程。完整协议见 `iteration-protocol.md`。

## 7. 证据而非印象

每个成熟度声明应附至少一种证据：

- 规则条款或不可行域；
- 数量／容量／时间／空间账；
- 流程、责任链或依赖图；
- 普通人日常实例；
- 故障、申诉或恢复案例；
- 历史事件如何沉积为制度、设施、习惯或物件；
- 正文场景中人物在知识边界内做出的选择。

没有证据的“已覆盖”应降为 `partial` 或 `gap`。

## 8. 常见失败模式

- **专名堆积**：机构、神祇、城市很多，但没有输入、人员和失效方式。
- **万能魔法**：只有功能，没有不可行域、维护、权限和反制。
- **制度自动执行**：权利没有义务主体、预算、办理、等待和申诉。
- **阶层贴标签**：只写上中下层，不写时间、证据、关系、冗余和风险如何分布。
- **知识全透明**：作者真相被所有角色准确掌握。
- **概念坍缩**：源头、中枢、操作者、继承者或后继现象因相邻而被写成同一事物。
- **伪继承与目的倒置**：功能相似被写成法统／权限继承，或以后世用途倒推古代唯一目的。
- **工具化国家**：一个国家只有资源、医疗、盟友或避难所功能，移除与主角／邻国的关系后便不再值得追问。
- **帝国目的论**：从古代工程目的直接跳到现代国家，把非均匀失效、幸存劳动、社会化和偶然分叉全部省略。
- **危机烟花**：事故推动剧情，却不留下工伤、债务、维修、纪念和改革。
- **接口替代实例**：通用模板写得完整，却没有任何一座地方能跑通普通星期二。
- **数字装饰**：数字彼此不闭合，也不改变设施、劳动和选择。
- **审计总分崇拜**：用一个分数掩盖关键环节为零。
- **候选山**：横向章节越来越齐全，却没有可行走地图、可办理机构、具体家庭和采用出口。
- **持久化混同**：把“可写候选文件”误当成“已采纳正典”，或把“暂不写正史”误当成“禁止保存候选”。
- **验证表演**：每轮重复全库统计，或用旧的成功快照掩盖本轮检查未完成。
- **最高级自证**：用“唯一／最发达”作气质标签，却没有比较范围、判据与反例。
- **并发协调膨胀**：共享索引被多路反复写入，协调成本超过创作本身。

## 9. 演进原则

框架本身也使用版本、证据和变更记录：

- `0.x` 允许字段和算法演进，但需提供迁移说明；`0.2` 的轮次信息只使用开放的 `extensions.iteration`，不改变 `0.1.0` schema；
- 确定性工具只检查可机器判断的结构，不宣称替代语义审查；
- 新检查必须来自真实失败案例或评测集，不因“看起来全面”无限加表；
- 项目适配规则高于默认规则；
- 任何自动补全都保留来源、状态和不确定性；
- 用前向测试、跨模型复核和实际创作返修持续改进。

## 10. 当前非目标

- 不自动决定作者的核心主题、终极谜底和价值立场；
- 不把所有世界强制改造成现代国家、市场或现实地球；
- 不保证联网事实核查；需要事实真实时另行检索可靠来源；
- 不替代 fiction-core 的六个专项创作技能；
- 不把 MCP 误称为创作模型。MCP 暴露的是契约、审计和路由能力，创意推演仍由调用它的模型完成。

## 11. 与完整世界创作的所有权边界

本引擎创建最小种子契约并管理来源、状态、真实性、依赖和失效；`fiction-core-zh:world-architect` 负责完整世界设定的实质创作。流程是：

```text
引擎压缩种子与设门 → world-architect 主写世界工件
→ 引擎审计与登记状态 → 再路由人物／故事
```

一次性 `seed` 回答可由引擎直接完成最小候选。进入 `candidate` 或 `instance` 时，不应让两个技能分别生成两份竞争的世界设计。
