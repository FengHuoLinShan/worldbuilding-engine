# 小说技法蒸馏

提炼高层机制，不复刻作者的独特措辞、句法指纹或表面风格。用功能对照区分普遍原理、类型惯例、媒介特性和单书选择。

## 路由任务

先识别用户要完成的动作：

1. **蒸馏作品**：从全文或分卷建立证据化技法图谱。
2. **分析局部**：解释一个章节、场景或句段为何有效/失效。
3. **迁移原创**：把已验证机制转化为新故事的设计选项。
4. **诊断改稿**：定位根因、安排修订顺序；未明确要求时不大段重写。

读取 [workflows.md](references/workflows.md) 中对应流程。全维度任务再读取 [craft-atlas.md](references/craft-atlas.md)；需要策略对照时读取 [classic-comparisons.md](references/classic-comparisons.md)。只加载当前任务需要的文件。

## 与世界引擎协作

项目已有 `world-state`、正典或候选设定时，`worldbuilding-engine` 继续拥有来源、权威状态、世界约束、依赖和失效传播；本技能只拥有文本证据、技法比较与 `technique_card`。迁移结果要交回实际工件所有者，不能用写法建议越权改写世界正典。

若 MCP 提供 `world_craft_packet`，可先用它生成十二面骨架和证据门；该包固定处于 `scaffold/unassessed/BLOCKED`，不能视为审稿完成。`world_text_surface_audit` 可检查解析覆盖、重复、配置词项和表面节律信号，但 `surface_regression_gate: PASS` 也不替代近读。诊断用户自己的稿件时由 `fiction-core-zh:story-editor` 主要拥有 finding 与返修归因；完成近读后可用 `world_craft_review_check` 检查报告字段与覆盖，`ready_for_host_decision` 仍不等于文学通过。

研究名家风格时，用 `world_craft_packet` 的 `distill_style` 模式，并提供作品、原作语言和版次／译本。它把证据压成项目本地的叙事控制项，不把作者标签当成仿写指令；句法、节奏和措辞结论必须回到原作语言核验。

## 读取材料

- 优先读取用户提供的原文、完整必要章节和上游大纲/设定。
- 分析长篇时先盘点章节边界、卷界、作者后记和版本；不要把抽样印象称作全书规律。
- 在 skill 根目录处理本地中文章节文本可运行：

```bash
python3 scripts/corpus_probe.py /absolute/path/to/novel.txt
python3 scripts/corpus_probe.py /absolute/path/to/novel.txt --json --chapters
```

统计只描述文本表面，不证明文学因果。必须回到具体场景做近读。完整稿审计应同时声明期望章节数和范围；章节解析失败、文本截断或范围不匹配必须阻断，不能静默降级为单个片段。

## 保持证据等级

分开记录证据来源和结论强度。

`source_type` 表示来源：

- `primary_text`：目标小说正文；
- `author_statement`：作者总结或访谈中的自述；
- `corpus_metric`：可复算的语料统计；
- `classic_text`：名著原文中的功能对照；
- `secondary`：版本说明或可信研究，仅作补助。

`claim_grade` 使用 [workflows.md](references/workflows.md) 的 `E0–E3`，表示结论从印象到可迁移的强度。推断写在 `inference` 字段，不冒充证据来源。

不要把作者自述当成已实现效果，也不要把读者印象伪装成作者意图。重要技法至少寻找两个不同位置的正例，并给一个反例、代价或适用边界。证据不足时明确写“待验证”。

## 使用十二面覆盖

按 [craft-atlas.md](references/craft-atlas.md) 的十二个检查面工作：创作契约、表达主题、结构、因果对抗、人物关系、视角信息、世界社会、场景节奏、对话行动、情绪氛围、语言意象、连载连续性与修订。

- 用户要求“所有方面”时先做十二行浅层覆盖矩阵，每一面标为 `finding`、`not_applicable` 或 `insufficient_evidence`；再按优先级逐层深审，每次只设一个主层。覆盖矩阵完成后才能因停止门结束。
- 局部材料只判断它能支持的层级。例如一段正文不能证明全书结构。
- 先修上游：契约/主题 → 世界约束 → 人物/结构/因果（往返校正）→ 信息/场景 → 语言/copy。

## 做功能对照

每次只比较同一个写作难题：

```text
写作问题
→ 已观察策略的解法及代价
→ 名著的另一种解法及代价
→ 共同原理
→ 何种条件下选哪一种
```

选择一至三部最相关的经典，不罗列书单，不做笼统高下排名。翻译作品的句法和用词比较必须注明译本限制；跨时代作品要区分章回体、报刊连载、实体长篇与当代网文的媒介差异。

## 输出技法卡

使用 [workflows.md](references/workflows.md) 的唯一规范 `technique_card` 模板。短回答可压缩字段，但保留 `source_type`、`claim_grade`、机制和边界。风格蒸馏还保留 `style_evidence` 与 `narrative_controls`，让观察能回测为原创项目中的具体控制项。

## 迁移而不照搬

- 抽象“身份改变信息与行动权限”，不要复制塔罗、序列、灰雾或具体组织形态。
- 抽象“变化轴 + 稳定轴”，不要规定八卷及固定卷序。
- 抽象“规则制造解法与代价”，不要复制能力名称和战斗桥段。
- 抽象“物质日常承载异常”，不要套用维多利亚装饰清单。
- 保留用户作品的题材、声音、人物伦理和媒介约束。

## 正文交接的反机械化门

把知识边界、正典与场景结果作为 `hard_invariants`，同时明确人物声线、冲突载体、节奏和感官中心的 `variation_obligations`，并保留 `prose_freedoms`。原则首次建立后，后续优先展示变化、误读或代价；对白已经表达清楚时不默认增加旁白复述；未改变决策的完整清单应概括。不同人物先从身体、职业、欲望和损失出发，不能都使用完整的证据法或授权法三段论。

## 完成门槛

交付前检查：

- 结论能否指向原文位置；
- 是否把相关性误写成因果；
- 是否给出反例或代价；
- 名著对照是否解决同一问题；
- 建议是否比原问题更具体、且没有要求用户变成另一本书；
- 是否清楚区分可迁移原理与单部作品的独有实现。
